# Road to Ironman v4 — "un entrenador de verdad", COROS y plan general (build contract)

> 2026-11-09. Owner request: (1) workouts must be concrete, like a real coach prescribing a specific
> session with goals to hit (heart rate, pace/power, RPE, sensations), and the coach must be better
> everywhere in the app; (2) friends use COROS instead of Garmin: onboarding keeps three things to
> connect (watch = Garmin **or** COROS, Claude, calendar) with a clear step-by-step for COROS;
> (3) a **general view** that plans several weeks at a high level ("this week descarga, next one more
> volume…") without detailing every workout. **The weekly planning stays exactly as it is.**
> `docs/V2.md`, `docs/ARCHITECTURE.md` and `docs/DESIGN.md` still apply unless this file says otherwise.

## 1. Shared pure modules (DONE — use them, do not fork them)

All in `src/domain`, exported by the barrel, unit-tested, and mirrored **verbatim** to
`supabase/functions/_shared/planning/domain/` by `node scripts/sync-domain-mirror.mjs`
(`npm run sync:mirror`; `mirror.test.ts` fails when the copy is stale). Mirrored modules import only
each other and `types`. If you change one of them, re-run the script.

- **`zones.ts`** — research 02 §2.1/§2.3 tables → `zoneTargets(sport, intensity, thresholds, { raceDistance, leg })`
  = `{ hr, pace, power, rpe, feel, hrEstimated }` (ppm from `thresholds.lthr` = running LTHR, bike ×0.97;
  without it LTHR ≈ 0.895/0.87 × `maxHr`, flagged `hrEstimated`; swim = CSS pace, never HR; strength RPE 6–7;
  race pace by race distance). `stepTargets(step, workout, thresholds, opts)` (explicit `step.target` wins),
  `stepIntensity`, `mainSet`, `mainTargets`, `sessionHrRange` (expected whole-session average HR, time-weighted),
  `sessionRpe`, `athleteZones(thresholds)` (table + `missing`), formatters `formatHrRange` ("145–151 ppm"),
  `formatPaceRange` ("5:08–5:48 /km", "1:48–1:55 /100 m"), `formatPowerRange`, `formatRpe`, `formatStepMinutes`
  (0.5 → 30"), `formatStepAmount`, `targetParts` (coach order per sport), `zoneName`.
- **`prescription.ts`** — `stepLines(workout, thresholds, opts)` (amount, label, zone, targets[], cue, note),
  `targetSummary` ("3×8' Z4 · 162–168 ppm · 4:27–4:44 /km · RPE 7–8"), `sessionFeel`, `prescriptionText`
  (plain text: Objetivo / Estructura / Claves / Lo has hecho bien si / Si no es tu día) for calendar notes and ICS.
- **`season.ts`** — `buildSeason({ today, races, level, weeklyHoursTarget, weekPlans, horizonWeeks })` →
  `{ targetRace, weeks: SeasonWeek[], warnings, summary }` from this week to the target race week (or 8 weeks).
  `SeasonWeek` = weekStart, number, kind (`load|push|recovery|rest|taper|race|transition`), label ("Carga",
  "Más volumen", "Vuelta a la carga", "Descarga", "Semana libre", "Pico", "Afinamiento", "Carrera", "Carrera B",
  "Transición", "Recuperación"), phaseLabel ("Base 2", "Construcción 1", "Mantenimiento"…), focus, why,
  volumeFactor, targetMinutes, trend, race, plan, editable, isCurrent. `applyWeekPlan(info, plan, weeklyHours)`
  applies an override to a `PhaseInfo`; `canOverride(info)` (prep/base/build weeks without a race only);
  `WEEK_PLAN_OPTIONS` (picker labels/help).
- `periodization.ts`: maintenance weeks (no race) now build 0.95 → 1.00 → 1.05 after each descarga (same
  descarga weeks as before).

## 4. Edge functions

- `planning/changes.ts` strict schemas accept `step.target` (ranges), `step.cue` (≤ 200), `step.leg`, and
  `coaching` on drafts/patches.
- `planning/phase.ts` becomes an adapter over the mirrored `domain/periodization.ts` (+ week plans via
  `applyWeekPlan`), so the AI coach, Claude and the briefing see the same week the app shows. Server `Race`
  gets `createdAt` (RACE_COLS + mapper).
- `planning/context.ts`: `athlete.zones` (compact `athleteZones`), `athlete.watchBrand`, `season` (compact
  `buildSeason`, ≤ 16 rows), workouts with `coaching` and a `targets` line (`targetSummary`).
- Coach (`coach/*`): flat change gains `steps` (nullable array of {kind, durationMin, distanceM, repeat,
  intensity, cue}) and `objective`, `keys`, `success`, `planB`; output gains `week_plans` (nullable array of
  {week_start, kind, target_minutes, note}) stored in `coach_jobs.extras.weekPlans` (chat). Lenient parsing:
  drop a bad step or field, never the whole change; clip texts. Prompt rewritten around a coaching method:
  every session = objective + structure + targets copied from `athlete.zones` (never invented) + RPE and
  sensations + success criterion + plan B; feedback on recent sessions (avgHr/RPE/feel vs plan); weekly
  narrative from the season (carga/descarga); several weeks → `week_plans`, not workouts. Device-neutral
  ("tu reloj Garmin o COROS"). Mind the Workers AI budget (no bigger context than needed).
- Briefing: per workout `coaching` + `targets`; yesterday plan vs done; the script says one concrete target,
  one sensation and the success criterion of the key session.
- MCP: instructions (coaching standard, COROS connector, general plan); `get_planning_context` with zones,
  season and watch brand; `propose_plan_changes` documents targets/cue/leg/coaching; **new tool
  `set_week_plans`** (write, applied directly, source `claude`; Mondays this week…+52; clear list) → 10 tools;
  `log_daily_metrics` `source?: 'garmin'|'coros'` (default from the profile's watch); `get_plan_for_device`
  device-neutral (Garmin JSON + provider-neutral steps for COROS: HR bpm and % LTHR, whole-second pace, W;
  swim/strength "créalo a mano en COROS"), interval sets grouped into one repeat, brick legs from steps,
  explicit targets first; ICS description = `prescriptionText`.

## 6. COROS — what we tell a friend (research 2026-11-09, `docs/research` + COROS docs)

COROS has no personal API key (only a partner programme). Two complementary paths, both free:
1. **Apple Salud (automatic):** COROS app › Perfil › Ajustes › Apps de terceros › Sincronización de datos ›
   Apple Health (Salud) → activar todo. Then Road to Ironman reads workouts, sleep (hours), resting HR, HR and
   steps through HealthKit. No HRV/VO2max, no history before enabling; data arrives when the COROS app syncs
   the watch (open it after training and in the morning).
2. **Claude + official COROS connector (recommended):** claude.ai › Personalizar › Conectores › Explorar ›
   COROS (or custom connector `https://mcp.coros.com/mcp`, EU `https://mcpeu.coros.com/mcp`), sign in with the
   COROS account. Claude reads HRV, sleep, resting HR, recovery, load and activities and saves them with our
   `log_daily_metrics` (source `coros`) / `log_completed_activity`; it can create run/bike/trail workouts in the
   COROS calendar (they reach the watch on sync; no swim/strength creation, no move/delete yet → delete old
   ones by hand). Set the same thresholds (FC máx, FC umbral, ritmo umbral, FTP) in both apps.
3. Without Claude: copy the session into COROS app › Perfil › Biblioteca de entrenamientos › "+".
