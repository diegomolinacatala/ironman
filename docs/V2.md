# Road to Ironman v2 — "tu coach de bolsillo" (build contract)

> 2026-10-27. Owner feedback on build 5: the app did too much and felt like a planner. v2 is a
> **simple, really functional personal coach**: it reads Garmin, lives in your calendar, you talk
> to it, you photograph your meals, and every morning it tells you (out loud) how you slept and
> what today looks like. `docs/ARCHITECTURE.md` still applies unless this file says otherwise.

## 1. The experience

1. **Forced, guided onboarding** (every user, including existing ones: the v2 migration resets
   `profiles.onboarded_at`). One idea per screen, progress bar, big friendly visuals, Spanish (tú):
   1. *Bienvenida* — name, what the app does in 3 lines.
   2. *Tu objetivo* — next race (name, date, distance; "Aún no tengo carrera" allowed) + hours/week.
   3. *Garmin* (**required**) — 3 guided micro-steps: open `https://connect.garmin.com/app/settings/personalApiToken`
      in the in-app browser (expo-web-browser) → "Crear clave → 1 año → Copiar" → back in the app,
      paste (clipboard detection / paste button) → `connectGarmin` validates + first sync → success
      screen with what was imported ("28 días: sueño, VFC, 9 actividades"). Errors explain what to do.
   4. *Claude* (**required**) — (a) AI consent sheet (sets `aiConsentAt`; names the AI provider, the data
      categories and that it can be withdrawn — Garmin clause 15.10); (b) "Conecta tu Claude":
      create an `mcp` token, copy the URL automatically, open `https://claude.ai/settings/connectors`,
      show the 3 steps (Añadir conector personalizado → nombre "Road to Ironman" → pega la URL);
      (c) **live verification**: poll `listTokens()` every 3 s while visible; connected when that
      token's `lastUsedAt` is set (claude.ai calls our MCP endpoint when the connector is added).
      Continue is enabled when connected; a discreet "Saltar por ahora" appears after 45 s.
   5. *Calendario* — explain both directions (we read busy time; we write your workouts with an
      alarm), request permission, pick calendars to read, turn on "Añadir mis entrenos al calendario"
      (`useTrainingCalendar().enable()`), preview of how an event looks. Denied → explain Ajustes,
      allow continuing.
   6. *Informe de cada mañana* — pick the time (default 07:00) → notification permission →
      `notificationPrefs.morningSummary/morningTime`; show how to add the lock-screen widget.
   7. *Tu plan* — generates the first 2 weeks (`requestCoach({ mode: 'plan_week' })`, apply the
      proposal automatically), progress copy ("Leyendo tu Garmin… Mirando tu calendario…"),
      falls back to the rules engine as today. Sets `onboardedAt` → Hoy.
   Demo mode (no backend): every step works with simulated success; web skips native steps.
2. **Three tabs**: **Hoy**, **Plan** (route `week`), **Tú** (route `me`). Juntos and Progreso leave
   the tab bar (routes `/together`, `/progress` in the root stack, linked from Tú).
   A persistent **coach accessory** (iOS 26 `NativeTabs.BottomAccessory`; floating bar on web)
   with two actions: 🎙 "Cuéntaselo a tu coach" → `/talk`, 📷 → `/meal?source=camera`.
3. **Hoy** — greeting + date + race chip; **Informe de hoy** hero (headline, sleep row, ▶ Escuchar,
   or "Preparar mi informe"); **today's session** (structure, time, "En tu calendario ✓");
   **Comidas de hoy** (photo thumbnails, kcal, totals, + Foto); **Mañana** strip. Pull to refresh
   also syncs Garmin.
4. **/briefing** (`?play=1` autoplays; opened by the widget and the morning notification) —
   generates if missing, sleep card (score ring, hours, stages bar, HRV vs baseline, resting HR,
   Body Battery), today's plan, focus tip, the script with play/pause/progress (`useSpeaker`),
   "Actualizar", Garmin attribution ("Datos de Garmin").
5. **/talk** — full-screen voice coach: big mic → live transcript → "Entendiendo…" → coach reply
   (optionally read aloud) + list of plan changes + "Aplicar cambios" / "Ahora no", chips for what it
   remembered (`memory`) and the imprevisto it logged (`lifeEvent`). Keyboard fallback. Multi-turn
   within the session (`history`).
6. **/meal** — camera or library (or describe it by voice/text) → "Analizando…" → editable result
   (description, items, kcal/HC/proteína/grasa, meal slot chips, tip) → Guardar (`createNutrition`
   + `saveMealPhoto`). Analysis failure → manual form with the same fields.
7. **Calendar sync** — planned workouts of [today − 1, today + 21] are written to a dedicated
   "Road to Ironman" calendar (title with sport emoji, e.g. "🏃 Rodaje suave · 50'", notes with the
   structure + `roadtoironman://workout/<id>`, alarm 30' before) and kept in sync. That calendar is
   never read back as busy time.
8. **Lock-screen widget "Informe de hoy"** (`BriefingWidget`: accessoryRectangular / Circular /
   Inline + systemSmall) → `roadtoironman://briefing?play=1`; shows today's headline once generated.
   Morning local notification at `morningTime` → `/briefing?play=1`.

## 3. Backend contracts (Supabase)

### Migration `supabase/migrations/20261027000100_v2.sql`
- `daily_metrics`: `sleep_deep_min`, `sleep_light_min`, `sleep_rem_min`, `sleep_awake_min`
  (integer 0..1440), `sleep_start`, `sleep_end` (timestamptz).
- `briefings` (user_id, date, headline ≤120, sleep_verdict, sleep_summary, script ≤4000, focus,
  sleep jsonb, model, created_at, updated_at; PK (user_id, date)); RLS: select own; no client writes.
  Added to the realtime publication in a `*_platform.sql` migration.
- `coach_jobs.extras jsonb` = `{ "memory": string[], "lifeEventId": uuid | null }`.
- `update public.profiles set onboarded_at = null;` (everyone sees the v2 onboarding once).

### `POST /functions/v1/briefing` (user JWT verified in code, like `garmin`)
Body `{ date: "YYYY-MM-DD", refresh?: boolean }` → `200 Briefing` (camelCase, `engine: "ai"`).
If a row exists for (user, date) and not `refresh` → return it (works without the API key).
Otherwise: Garmin sync for this user when connected and `last_sync_at` older than 30 min (errors
ignored), build context (last night's sleep incl. stages, HRV vs 7-night baseline, resting HR,
Body Battery, today's + tomorrow's workouts with steps, phase/race countdown, yesterday's load,
busy blocks WITHOUT titles), the AI (see *AI provider* below; effort `low`, structured output), upsert row.
Errors `{ error, message }`: 401 `unauthorized`, 400 `bad_request`, 403 `consent_required`,
429 `rate_limited` (12/24 h via `ai_usage`), 503 `ai_unavailable`, 500 `internal`.
Script rules: Spanish (Spain), tú, warm and concise, 110–200 words, no markdown/emoji/lists,
numbers and units written for speech ("siete horas y veinte minutos", "zona dos", "kilómetros").

### `POST /functions/v1/meal` (user JWT verified in code)
Body `{ date, time, imageBase64?, text? }` (at least one; base64 ≤ 2 MB → else 413 `too_large`)
→ `200 MealAnalysis` (`engine: "ai"`). Vision model, effort `low`, structured output; context:
today's workouts (for the tip) — nothing else. Same error codes; 40/24 h. Nothing stored.

### AI provider (zero cost)
The owner wants the app to cost nothing, so `coach`, `briefing` and `meal` call **Cloudflare
Workers AI** (free tier, 10.000 neuronas/día shared with the Tasks app) through our worker
`cloudflare/ai` (`POST /v1/chat`, bearer `AI_SHARED_SECRET`, deployed at
`https://ironman-ai.<tu-subdominio>.workers.dev`). Supabase secrets `AI_WORKER_URL` + `AI_WORKER_SECRET`;
models `AI_MODEL` (default `@cf/nvidia/nemotron-3-120b-a12b`, coach + briefing) and `AI_VISION_MODEL`
(default `@cf/meta/llama-4-scout-17b-16e-instruct`, meal), picked with live tests on 2026-10-27
(GLM-5.3 / DeepSeek V4.1 are paid-plan only). Claude (`ANTHROPIC_API_KEY`) is only an optional
fallback. When the daily quota runs out the functions answer 503 and the app falls back to its local
templates / rules engine. Voice recognition and text-to-speech run on the iPhone (free, offline).

### `coach` changes
Output schema adds `memory: string[]` (0–3 short facts/preferences worth remembering) and
`life_event` (kind, title, start_date, end_date|null, severity 1–3, body_area|null, notes) | null.
The job appends memory lines to `profiles.coach_notes` (dedupe, keep ≤ 2000 chars, newest kept),
inserts the life event, writes `coach_jobs.extras`. Prompt: messages with `channel: "voice"` are
speech transcripts (fix obvious recognition errors, ask nothing back: decide). Injuries → always
"consulta a un profesional" + conservative changes.

### Garmin
Parse sleep stages + start/end (`deepSleepSeconds`, `lightSleepSeconds`, `remSleepSeconds`,
`awakeSleepSeconds`, `sleepStartTimestampGMT`/`sleepEndTimestampGMT` on `dailySleepDTO`, defensive
like the rest). First sync after connect covers 28 days (baselines); later syncs 14.

## 5. Visual direction

Keep the brand (Barlow Condensed numbers + Barlow text, ink & paper, lime only for the primary
action / "today") but make it calm and obvious: **one hero per screen**, generous whitespace,
big condensed numbers for the few metrics that matter, short sentences instead of dashboards,
progressive disclosure (details one tap away), soft entrance motion (Reanimated `FadeInDown`
30–50 ms stagger, springs, reduced-motion respected). Sport colours via `useTheme().sport()`.
No emoji in the app UI (SF Symbols via `Icon`); emoji are fine only inside calendar event titles.

## 6. Rules for every agent

- Read `CLAUDE.md`, `AGENTS.md`, `docs/ARCHITECTURE.md` §2/§10, then this file.
- No `npm install` / `npx expo install`. No `console.log` (use `logger`). Immutability. Files < 400

- UI: use `src/ui` primitives and theme tokens only (no raw hex), `Icon` (SF Symbols names in
  `src/ui/Icon.tsx`), haptics on key actions. ui-ux-pro-max checklist: 44 pt targets, one primary
  action per screen, loading/empty/error states with recovery, accessibilityLabel on icon buttons,
  Dynamic Type tolerant (no fixed text heights), colour never the only signal, 150–300 ms motion
  (Reanimated, respect reduced motion), safe areas, both themes.
- Native APIs guarded for web (`Platform.OS`), demo mode fully usable in `npm run web`.
- Tests: jest for pure logic and hooks you add (`await render(...)` in RTL 14); mock native
  modules. Run `npx tsc --noEmit` (zero errors in your files) and the relevant test command.
- Don't commit. Report: files changed, decisions, anything another agent or the orchestrator must do.
